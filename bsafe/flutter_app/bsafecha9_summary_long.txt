二、專案本身是什麼

B-SAFE 是一個智慧建築安全平台，核心目標是把工地、建築巡檢、缺陷回報與後續處理整合起來。手機 App 提供現場人員拍照上報、AI 協助分析、查看歷史紀錄、更新狀態、回覆公司訊息，以及巡檢相關功能。Web Dashboard 則提供公司人員查看報告、追蹤狀態、填寫跟進內容、管理報告流程。這兩端共用 Supabase，所以所有關鍵資料都存放在雲端，避免手機與電腦端資料不同步。

從內容來看，這個專案不只是一般的報告系統，而是結合了：
- 圖片上報與缺陷識別
- AI 分析與風險分類
- 報告歷史與狀態追蹤
- 公司與工人的雙向溝通
- 巡檢 session 與 floor plan 管理
- 雲端同步與資料一致性

根據聊天內容，你在意的是：
- title 是不是 AI 回傳的
- AI 沒有回傳時系統怎麼處理
- 報告標題會不會是使用者手動輸入
- 標題與分析結果之間的關係

這說明你不只是要 AI 幫你寫功能，還想理解資料流與生成邏輯的來源。

四、你遇到的主要困難

1. Flutter 跑不起來

最明顯的問題是你一開始執行 flutter run 時，命令路徑不對，導致找不到 pubspec.yaml。這表示你的專案其實在另一個資料夾下，而不是你當時 cd 進去的地方。這種錯誤很常見，但會直接阻斷開發流程，所以你需要 AI 幫你快速定位正確目錄。

2. Git 版本混亂

你一直在確認「是不是有新版本」、「現在是不是最新」、「昨天有沒有 push 新 version」。這代表你當下對版本狀態不太確定，需要靠 git log、remote branch、commit date 來驗證。目前的資料顯示，最新版本最後停在 2026-04-23 的 c2c2cf9，並沒有你以為的昨天版本。

3. 資料庫太 technical，不好講

你原本的 Slide 2 看起來包含 key fields、schema、JSONB、PK/FK 等欄位，但你後來明確說不想太專業、不想顯示 key fields。這反映出你正在解決「技術正確性」與「簡報可讀性」之間的衝突。你需要的不是資料庫工程文件，而是給評審看的清楚說明。

4. AI 與報告欄位的行為需要釐清

你想知道標題是不是 AI 生的、prompt 放哪裡、資料怎麼流、圖片和文字怎麼存，這些都說明你的專案不是單純 CRUD，而是有 AI 判斷與 fallback 邏輯的流程。這類問題如果不釐清，報告與 UI 就可能出現不一致。

5. 需要把聊天內容變成可重用上下文

你最後想把整份對話整理成 txt，是因為這個對話實在很長，而且跨越很多主題。你希望後續 AI 能直接讀這份檔案，知道專案背景，不用每次重新交代。

五、這份對話中 AI 幫你建立的核心理解

1. B-SAFE 的資料結構

AI 幫你釐清了資料庫不是只存圖片，而是會存報告本體、AI 結果、對話、公司回饋、狀態、時間、定位與巡檢 session 等資料。圖片與 floor plan 則通常存在 Supabase Storage，資料表裡只存引用。

2. 報告標題不是純手動欄位

報告標題有一部分是來自 AI 回傳，沒有回傳時則用 fallback 邏輯，例如「Building Safety Issue」這類固定詞。這讓你的 app 可以在 AI 輸出不完整時仍然生成合理的標題。

3. AI prompt 是程式的一部分

你找到 prompt 位置後，就能知道 AI 的行為不是黑盒子，而是可以透過程式碼控制的。這代表之後如果要改分類規則、輸出格式、缺陷描述方式，都可以直接調整 service 中的 prompt。

4. Supabase 是整個系統的核心

不是只有存資料，而是同時負責：
- 雲端資料庫
- 圖片 / floor plan 儲存
- Mobile 與 Web 的共同來源
- 即時同步與資料一致性

也就是說，Supabase 是整個 B-SAFE 的資料樞紐。
